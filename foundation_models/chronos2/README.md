# Chronos-2 single-radar benchmark

This package runs the PULSAR single-radar forecast benchmark on Chronos-2. It
uses the CSVs generated by `dataset_generator/generate_datasets.py` in this
branch and does not depend on the `foundation-models` branch.

## Protocol

- Five radar types and four error levels are evaluated separately under each
  fixed or varying profile. A complete profile has 20 datasets.
- Each `1000x128` dataset has 700 train, 100 validation, and 200 test sequence
  files. Newly generated single-radar files contain 129 observed rows: one
  arrival-time anchor and 128 intervals. The loader follows the TimesFM rule
  and drops that anchor. Older files generated with a fixed time duration can
  have variable row counts; the loader retains their anchor unless they have
  exactly 129 rows with a zero first observed delta.
- The first 96 selected rows form the context and the next 32 form the target.
  Each sequence contributes one window. Sequences are never concatenated.
- For PRI, the context is `Measured_Delta_TOA` and the target is source `PRI`.
  For Frequency, PW, AOA, and Amplitude, the same observed column supplies
  context and target. The multivariate task uses all five channels.
- False pulses and echoes remain in the observed context. Only `R_SINGLE`
  target positions contribute to evaluation and fine-tuning loss. Sequences
  with no emitter targets are excluded and counted.
- Reported MAE, RMSE, and gate hit rate are averages of per-sequence scores,
  matching the TimesFM report structure. Ordinary AOA error is retained for
  comparison; circular AOA metrics are included as extra columns.

The code fails if a selected dataset or expected sequence file is missing.
Short sequences are excluded and counted. Before the generator change, the
local `1000x128` files had 2,559 usable fixed-profile test windows out of
4,000 and 2,180 varying-profile windows. Varying stagger clean had zero.
Regenerating the single-radar datasets with the updated generator gives each
sequence the anchor and 128 observed intervals. No padding or dataset-size
substitution is performed. The data are ignored by Git; generate them once
and reuse the same CSVs for all model comparisons. Existing TimesFM reports
can be compared numerically only when they used these exact CSVs and the same
sequence inclusion rule.

## Setup

From the repository root, in an environment with Python 3.10–3.12 and an
appropriate PyTorch installation:

```powershell
python -m pip install -r requirements.txt
python -m pip install -r foundation_models/chronos2/requirements.txt
```

The default model is `amazon/chronos-2`. The first actual model run downloads
its weights. Use `--device cpu` if CUDA is unavailable.

## Run the full single-radar experiment matrix

From the repository root, the runner executes zero-shot evaluation for all
five PDW parameters and the joint five-channel task on fixed and varying
profiles, then trains and evaluates a separate LoRA adapter for each task and
profile, then evaluates the PRI and joint adapters across profiles. Each
evaluation covers all five radar types, four error levels, and 200 test
sequences per condition.

```powershell
python -m foundation_models.chronos2.run_all --dry-run
python -m foundation_models.chronos2.run_all --resume
```

`--dry-run` prints all 26 stages. `--resume` skips only stages with complete
full-size metrics (and a checkpoint for LoRA stages), so an interrupted run can
continue. A prior two-sequence smoke test does not count as complete. Omit
`--resume` to rerun every stage after changing the dataset CSVs. Use
`--device cuda` on a machine with a CUDA PyTorch build; all 12 LoRA trainings
can take substantial time on CPU. This
runner uses the existing local CSVs and does not regenerate datasets.

Check all 20 test conditions without downloading the model:

```powershell
python -m foundation_models.chronos2.evaluate --profile-mode fixed --coverage-only
python -m foundation_models.chronos2.evaluate --profile-mode varying --coverage-only
```

The evaluator refuses to start a full run if a selected condition has no
complete window. If coverage reports zero for varying stagger clean,
regenerate that `1000x128` dataset with the updated generator.

## Zero-shot evaluation

First try one condition:

```powershell
python -m foundation_models.chronos2.evaluate --profile-mode fixed --target-param PRI --radar-type stable --error-level clean --max-test-seqs 2
```

Then evaluate all five single-parameter tasks and the five-channel task over
the full fixed profile:

```powershell
python -m foundation_models.chronos2.evaluate --profile-mode fixed --target-param all
python -m foundation_models.chronos2.evaluate --profile-mode varying --target-param all
```

Each task writes `metrics.csv`, `report.md`, and diagnostic plots under
`results/chronos_2/zero_shot/`.

## LoRA fine-tuning

The official Chronos-2 `fit` API trains one fixed 96-to-32 window per sequence.
For the PRI task, each training array has observed spacing in its first 96
positions and true PRI in its final 32 positions. This reproduces the
input/target task, although Chronos-2's native quantile loss differs from
TimesFM's Huber loss. The native multivariate loss also does not use TimesFM's
five channel weights. `min_past=96` prevents training on shorter windows.

```powershell
python -m foundation_models.chronos2.train --profile-mode fixed --target-param PRI
python -m foundation_models.chronos2.train --profile-mode varying --target-param PRI
python -m foundation_models.chronos2.train --profile-mode fixed --target-param multivariate
python -m foundation_models.chronos2.train --profile-mode varying --target-param multivariate
```

Run `train` separately for Frequency, PW, AOA, and Amplitude to obtain their
dedicated adapters. The default step budget is three passes over the training
sequence count with batch size 64. Chronos-2 samples training sequences with
replacement, so this is a step-budget match, not identical epoch traversal.
Checkpoints are written to `models/chronos2_lora/` and test metrics to
`results/chronos_2/lora_sft/`. The checkpoint directory is ignored by Git.

For a small integration run, add `--radar-type stable --error-level clean
--max-train-seqs-per-dataset 4 --max-val-seqs-per-dataset 2 --max-test-seqs 2
--steps 1`. This still downloads the model and requires its dependencies.

## Cross-profile transfer

After training both fixed and varying PRI and multivariate models:

```powershell
python -m foundation_models.chronos2.run_cross_evaluation --target-param PRI
python -m foundation_models.chronos2.run_cross_evaluation --target-param multivariate
```

These test fixed-trained checkpoints on varying-profile data and vice versa.
The current scripts cover single-radar data; interleaved data need a separate
task definition and emitter mask.
