# Chronos-2 LoRA SFT on new_complex_pri

Use `run_sft`, not the legacy `run_all` or `train` CLI, for this experiment.
This adds a separate SFT entry point; existing zero-shot defaults are retained.
No datasets are generated, edited or uploaded by this runner.

## Protocol

- Dataset root: `datasets/new_complex_pri/production/C1024_H32/single_radar`.
  Stored dataset size is `1000x1056`: 1024 observed context intervals and
  32 consecutive source future intervals, plus a stored arrival-time anchor.
- Fixed and varying profiles; eight radar types; clean and error_lv1 through lv7.
- PRI univariate, Frequency univariate, and five-channel multivariate.
- L=96/256/512/992, H=32, explicit `boundary` windows for every split.
  The context ends at observed interval 1023 and targets are 1024–1055.
  Shorter contexts use the last L observed intervals. No random window shifts.
- One independent LoRA adapter per profile/task/L: **24 adapters**. Each adapter
  pools all 64 radar/error conditions within its profile. Radar/error-specific
  adapters and cross-profile transfer are outside this experiment.
- Per adapter: 44,800 train windows (700 x 64), 6,400 validation windows
  (100 x 64), 12,800 test windows (200 x 64). Sequence IDs must be disjoint
  between splits within every radar/profile/error condition.
- PRI context uses observed Delta-TOA; its future target uses source PRI.
  Frequency retains the measured Frequency input/target definition. Joint SFT
  optimizes the Chronos quantile loss on all five channels, while evaluation
  reports PRI and Frequency. No future covariates are provided.
- Each fitting input is exactly L+32 long and `min_past=L`. This constrains
  Chronos's training crop to the intended boundary; no target values enter the
  context. Validation selects the minimum `eval_loss` (quantile loss, not MAE).
- Test CSV hashes, windows and plot sequence IDs are checked against the
  supplied completed zero-shot run. Default example: `seq_0800`.
- The source RNG still depends on error level. Thus error levels are independent
  source realizations, not paired corruptions. SFT versus zero-shot is paired
  using the exact same test data/windows; this does not change synthesis design.

## Budget and checkpoints

Defaults retain LoRA rank 16, alpha 32, learning rate 1e-5 and three expected
passes worth of samples. Chronos samples sequences with replacement, so
`--epochs` describes expected exposure, not guaranteed complete passes.
`--steps N` instead sets an explicit number of optimization steps per adapter.

Chronos batches count variates. `--train-batch-size 20` gives 20 univariate
sequences or four five-channel sequences per batch. Three expected passes mean
6,720 steps per univariate adapter and 33,600 per multivariate adapter.
Validation/checkpoint selection occurs every 500 steps and at the final step.
These are substantial training budgets; smoke timings do not estimate total
wall time with the full validation pool. `--batch-size` controls evaluation.

Every job starts from the base model, not the preceding adapter. Partial fits
are not resumed as optimizer runs: an interrupted fit restarts in a fresh
attempt directory. A completed adapter is reused only after input and weight
hashes match. After fitting, the saved adapter is reloaded for evaluation.
Result and checkpoint roots must be separate and cannot overwrite input data
or reference zero-shot results.

## Full run: execute manually after reviewing smoke results

```powershell
Set-Location -LiteralPath 'C:\Users\User\Desktop\DÇ'
if ((git branch --show-current).Trim() -ne 'long-seq-1024') {
    throw 'Aktif branch long-seq-1024 olmalı.'
}
$chronosSftOutput = Join-Path (Get-Location) ('results\chronos2\lora_sft\new_complex_pri\run_' + (Get-Date -Format 'yyyyMMdd_HHmmss'))

& "$env:USERPROFILE\bitirme-chronos2-venv\Scripts\python.exe" -B `
    -m foundation_models.chronos2.run_sft `
    --zero-shot-run results/chronos2/zero_shot/new_complex_pri/run_20261118_151924 `
    --profiles fixed varying `
    --tasks PRI Frequency multivariate `
    --context-lens 96 256 512 992 `
    --horizon 32 `
    --epochs 3 `
    --train-batch-size 20 `
    --batch-size 16 `
    --device cuda `
    --output-dir $chronosSftOutput

if ($LASTEXITCODE -ne 0) { throw 'SFT tamamlanamadı; son hata mesajını incele.' }
Write-Host "SFT raporu: $chronosSftOutput\report.md"
```

Add `--dry-run` to print the 24 jobs without reading datasets, loading weights,
creating outputs or training. Do not use `--smoke-test` for the full run.
The smoke flag caps each condition to 2/1/2 train/val/test windows and every
adapter to at most two optimization steps.

To continue an interrupted experiment, repeat its command with the **same**
`--output-dir` and add `--resume`. Set `$chronosSftOutput` to that existing
directory rather than creating a new timestamp. Code/configuration, reference
and dataset changes cause resume rejection. Device and evaluation batch size
may change; training settings are fixed. Do not edit the experiment code during
an active run if you intend to resume it later.

When the old VS Code terminal is unavailable, use:

```powershell
& .\foundation_models\chronos2\continue_sft.ps1
```

It leaves a running SFT process untouched, reports an already completed run,
or resumes the latest saved production run using `run_config.json`. It never
creates a new experiment. Use `-StatusOnly` to inspect without starting anything,
or `-RunDirectory <existing-run>` to select a specific experiment. A failed
process query stops this helper without launching a second trainer. Interrupted
individual fits restart; completed adapters are reused.

## Reports and comparisons after the full run

```powershell
$python = "$env:USERPROFILE\bitirme-chronos2-venv\Scripts\python.exe"
& $python -B -m foundation_models.chronos2.compare_context_mae --source $chronosSftOutput
if ($LASTEXITCODE -ne 0) { throw 'SFT MAE tablo üretimi başarısız.' }
& $python -B -m foundation_models.chronos2.plot_mae_comparisons --source $chronosSftOutput
if ($LASTEXITCODE -ne 0) { throw 'SFT profil/task karşılaştırmaları başarısız.' }
& $python -B -m foundation_models.chronos2.compare_sft `
    --zero-shot-run results/chronos2/zero_shot/new_complex_pri/run_20261118_151924 `
    --sft-run $chronosSftOutput
if ($LASTEXITCODE -ne 0) { throw 'SFT/zero-shot karşılaştırması başarısız.' }
```

- SFT results: `results/chronos2/lora_sft/new_complex_pri/<run>/`.
  Same metric/example/plot layout as zero-shot, with SFT titles. A full run
  has 1,536 condition rows, 307,200 sequence forecasts and 1,536 example PNGs.
- Weights: `models/lora_sft/chronos2/new_complex_pri/<run>/<task>/L<length>/<profile>/<attempt>/best_model`.
  Models remain Git-ignored.
- SFT Excel, eight table PNGs and CSV/Markdown tables:
  `outputs/new_complex_pri/lora_sft/mae_comparison/<run>/`.
- Fixed/varying and uni/multivariate comparisons (32 PNGs):
  `outputs/new_complex_pri/lora_sft/comparisons/<run>/`.
- SFT versus zero-shot comparisons (32 PNGs and 2,048 paired MAE rows):
  `outputs/new_complex_pri/sft_vs_zero_shot/<run>/`.
  Negative SFT minus zero-shot MAE means improvement. No radar/error averaging.

Exporters reject partial/smoke matrices. Output folders must be fresh; use an
explicit fresh `--output-dir` to rebuild reports. Numeric MAE values are checked
against all 200 per-sequence scores. Comparisons verify the same base model ID,
test CSV hashes and exact window manifest. The prior zero-shot runtime did not
record a concrete model revision (`model_commit` is null); preserve the existing
cached base weights/environment for the closest reproducible comparison.

Smoke outputs, training input audits and dataset coverage files are local
development artifacts and excluded by `.gitignore`. Raw dataset CSVs stay local.
