# TiRex-2 single-radar benchmark

This package evaluates the open-source TiRex-2 model on the same local
`1000x128` single-radar CSVs and 96-context/32-target windows used by the
Chronos-2 benchmark. It reuses the sequence loader and scoring functions in
`foundation_models/chronos2/` without importing or changing the Chronos-2 model.

## Scope

- Fixed and varying profiles, five radar types, and four error levels.
- Five separate univariate forecasts: PRI, Frequency, PW, AOA, and Amplitude.
- One joint five-channel forecast per condition.
- 200 test sequences per condition, with source `Radar_ID == "R_SINGLE"`
  positions scored and false/echo pulses retained in the observed context.
- The same MAE, RMSE, gate hit rate, and AOA metrics as the Chronos-2 evaluator.
- One plot for the first test sequence (`seq_0800`) in each condition.

The open-source TiRex-2 package only supports zero-shot forecasting. The
TimesFM/Chronos LoRA and trained cross-profile experiments therefore have no
TiRex-2 equivalent here. The joint task uses five target channels without
future covariates. The point forecast is TiRex-2's median (0.5 quantile).

## Separate environment

TiRex-2 requires NumPy 2, while the root `requirements.txt` requires NumPy
below 2. Keep `pulsar` for Chronos and use a separate environment:

```powershell
conda create -n tirex2 python=3.12 pip
conda activate tirex2
python -m pip install "torch==2.14.1+cu130" --index-url https://download.pytorch.org/whl/cu130
python -m pip install -r foundation_models/tirex2/requirements.txt
python -c "import torch, tirex2; print(torch.cuda.is_available())"
```

These commands are for the existing Windows machine with an NVIDIA GPU and a
driver supporting CUDA 13.0. If TiRex-2 reports that it cannot find `cl` on
Windows, follow its [Windows compiler guidance](https://github.com/NX-AI/tirex-2/issues/17)
in the new environment. Do not install the root `requirements.txt` into this
environment.

## Check and run

Run from the repository root. Coverage inspection works before TiRex-2 is
installed:

```powershell
python -m foundation_models.tirex2.evaluate --profile-mode both --coverage-only
```

Start with two test sequences:

```powershell
python -m foundation_models.tirex2.evaluate --profile-mode fixed --target-param PRI --radar-type stable --error-level clean --max-test-seqs 2 --device cuda
```

Then run all 12 zero-shot stages, including all 20 conditions per stage:

```powershell
python -m foundation_models.tirex2.run_all --dry-run --device cuda
python -m foundation_models.tirex2.run_all --resume --device cuda
```

The full results go under `results/tirex_2/zero_shot/`, with `metrics.csv`,
`report.md`, and diagnostic plots for each task. A two-sequence smoke result
does not qualify as complete, so `--resume` reruns it. If the dataset CSVs
change, omit `--resume` to rerun all stages. Data are read only and are never
regenerated by the evaluator.
